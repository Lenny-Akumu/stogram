# CLAUDE.md

Робоча назва проєкту: **[НАЗВА]** (ще не обрана, у коді — `app`, бандл `dev.lenny.app`, змінити, коли буде назва).

## Що будуємо

Власний клієнт Telegram з повністю своїм UI та функціями в стилі AyuGram (режим привида, збереження стертого, історія редагувань).
Це **не форк** AyuGram чи tdesktop. Пишемо з нуля на **Flutter + TDLib**.

- Платформи: Linux (основна для розробки, Arch), Windows, Android. Потім macOS та iOS.
- Одна кодобаза на всі платформи. ПК і мобілка відрізняються лише оболонкою (`shell`), а не логікою.

## Спілкування з власником

- Відповідай українською, неформально, як другу. Мат дозволений.
- Пояснюй коротко, без води. Якщо є кілька шляхів — дай рекомендацію, а не список.

## Стиль коду (обовʼязково)

- Коментарі тільки короткі й по ділу, коли без них незрозуміло. Ніяких довгих коментарів-пояснень до блоків.
- Жодних "слідів ШІ": без `// This function does…`, без коментарів до очевидного, без емодзі в коді й комітах, без банерів і TODO-есе.
- Імена змінних, класів, комітів — англійською. Рядки інтерфейсу — через локалізацію (`uk` за замовчуванням, `en` другою).
- Коміти: Conventional Commits англійською (`feat:`, `fix:`, `refactor:`…), коротко.
- Перед кожним комітом: `dart format .`, `flutter analyze` без помилок, тести зелені.

## Стек

- Flutter stable, Dart 3, null safety, `very_good_analysis` або `flutter_lints`.
- Стан: **Riverpod** (`flutter_riverpod` + `riverpod_annotation`).
- Навігація: **go_router**.
- TDLib: через FFI до `td_json_client`. Спершу оціни готові пакети на pub.dev (актуальність, підтримка desktop + Android). Якщо нічого живого — своя тонка обгортка в `lib/core/tdlib/` (окремий isolate, `Stream` апдейтів, `Future` для запитів з `@extra`).
- Локальна база для Ayu-функцій: **drift** (SQLite).
- Шрифти: `google_fonts` (список шрифтів кожного дизайну — в `docs/DESIGNS.md`).
- Секрети: `api_id` / `api_hash` з my.telegram.org через `--dart-define-from-file=env.json`. `env.json` у `.gitignore`, у репо лише `env.example.json`.

## Дизайни: архітектура скінів

Усі дизайни з `docs/designs/` мають бути доступні в застосунку як вибір у налаштуваннях «Вигляд».

- `Skin` — абстракція: токени (кольори, типографіка, радіуси, тіні, відступи) + фабрики компонентів:
  `MessageBubble`, `SideStrip`, `RevealPanel`, `ChatRow`, `Composer`, `AyuToggle`, `ChatHeader`, `SettingsScreen`.
- `Shell` — лейаут. Скін каже, яким шеллом користуватись.
- Логіка й дані не знають про скіни. Скін отримує готові моделі (чат, повідомлення, стан Ayu) і лише малює.
- Кожен скін має світлу і/або темну тему, як у макеті. Не вигадуй нових кольорів — бери з `docs/DESIGNS.md`.

### Головний шелл — `EdgeShell` (V3/V4)

Весь екран — це відкритий чат. Все інше сховане:
- По лівому краю — тонка вертикальна смуга чатів, по правому — смуга інструментів/контакту/Ayu. Як саме виглядає смуга, вирішує скін.
- **ПК:** наведення мишки в зону ~76–80 px від краю відкриває панель (`MouseRegion`). Панель ховається, коли курсор з неї йде. Чат під панеллю притемнюється.
- **Мобілка:** панелі відкриваються свайпом від краю, закриваються свайпом назад або тапом по затемненню.
- Анімації 180–240 мс, `easeOutCubic`. Поважати `MediaQuery.disableAnimations`.
- Скін Dock (V3) — виняток: смуги зверху (пошук і команди) та знизу (док з людьми).

### Порядок реалізації скінів

1. Каркас `EdgeShell` + скін **Monolith** (найпростіший, без блюру) — на ньому відлагоджуємо поведінку.
2. Решта V4: Soft Keys, HUD, Liquid Glass, Riso Tickets.
3. V3: Edge, Spines, Rail (з мінікартою розмови), Halo, Dock.
4. V2 як окремі шелли: Stage, Deck, Feed, Bento, Editorial.
5. V1 (класика: список + чат) — як `ClassicShell` з 5 скінами.

Якщо власник обере фаворита — він стає дефолтним, порядок можна переглянути.

## Ayu-функції (логіка в `lib/core/ayu/`)

- **Режим привида:** не надсилати онлайн (`setOption("online", false)` і не вмикати назад), не викликати `viewMessages`, не відправляти `sendChatAction` (друкує). Окремий перемикач «Читати без сліду при відповіді».
- **Збереження стертого:** кожне отримане повідомлення дублюється в drift. На `updateDeleteMessages` з `is_permanent: true` не видаляємо локальну копію, а позначаємо `deletedAt`. В UI стерте показується з позначкою (вигляд — за скіном).
- **Історія редагувань:** на `updateMessageContent` / `updateMessageEdited` зберігаємо попередню версію тексту з часом. В UI мітка «ред.» відкриває історію.
- Усі функції вмикаються/вимикаються в налаштуваннях, стан у drift або `shared_preferences`.

## Обмеження й правила

- У назві й іконці застосунку не можна використовувати слово «Telegram» і їхній логотип.
- Не копіювати код з AyuGram / tdesktop / Telegram Android: вони під GPL. Ідеї — так, код — ні.
- Ghost mode і збереження стертого порушують ToS Telegram. Тестувати на другому акаунті.
- Не логувати повідомлення, токени й номери телефонів. Номер в UI маскувати.
